# LaTeX-отчёты по предмету «Автоматизация процессов жизненного цикла ПО»

Шаблоны и стили для составления документов по ГОСТ 34.602-89 и ГОСТ 7.32-2017.

## Структура

| Файл | Назначение |
|------|-----------|
| `tz_style.sty` | Стиль технического задания (ГОСТ 34.602-89) |
| `tz_shortcuter.tex` | ТЗ для проекта «Shortcuter» (пример использования стиля) |
| `Makefile` | Сборка PDF |
| `images/` | Диаграммы, скриншоты, рисунки |

## Сборка

```bash
cd latex
make
```

Требуется установленный MiKTeX или TeX Live с пакетами:
- `tempora` (шрифт Times New Roman)
- `titlesec`, `fancyhdr`, `enumitem`, `longtable`, `tabularx`, `caption`, `hyperref`

## Использование стиля ТЗ

### Быстрый старт

```latex
\documentclass[14pt, a4paper]{extarticle}
\usepackage{tz_style}

% Данные проекта
\newcommand{\developer}{ООО «Название»}
\newcommand{\customer}{Московский Политех}
\newcommand{\systemtype}{Веб-приложение}
\newcommand{\systemname}{«Название»}
\newcommand{\systemfullname}{Полное название системы}

\begin{document}

% Лист утверждения (ГОСТ 34.602-89)
\approvalpage{\developer}{\customer}{\systemtype}{\systemname}{27}{01.01.2025}

% Содержание
\tableofcontents
\newpage

% 1. Общие положения
\section{Общие положения}
% ...

% 2. Назначение и цели
\section{Назначение и цели создания системы}
% ...

% 3. Характеристика объекта
\section{Характеристика объектов автоматизации}
% ...

% 4. Требования
\section{Требования к системе}
% ...

% 5. Состав работ
\section{Состав и содержание работ по созданию системы}
% ...

% 6. Контроль и приемка
\section{Порядок контроля и приемки системы}
% ...

% 7. Документирование
\section{Требования к документированию}
% ...

% Подписи
\signatureblock{\developer}{Разработчик}

% Приложение с сокращениями
\abbreviations{
	ТЗ & Техническое задание \\
	\hline
}

\end{document}
```

### Команды стиля

| Команда | Описание |
|---------|----------|
| `\approvalpage{разработчик}{заказчик}{тип}{название}{листов}{дата}` | Лист утверждения по ГОСТ |
| `\signatureblock{организация}{должность}` | Блок подписей в конце документа |
| `\abbreviations{...}` | Приложение с перечнем сокращений (longtable) |
| `\startappendix` | Переход к приложениям (нумерация А, Б, В...) |

### Особенности оформления

- Поля: левое 30 мм, правое 15 мм, верх/низ 20 мм
- Шрифт: Times New Roman (tempora), 14pt
- Интервал: 1.5
- Абзацный отступ: 1.25 см
- Разделы: с новой страницы, по центру, прописными буквами
- Подразделы: с абзацного отступа, полужирные
- Таблицы: подпись сверху слева «Таблица X — Название»
- Рисунки: подпись снизу по центру «Рисунок X — Название»
- Нумерация таблиц и рисунков — в рамках раздела

## Создание нового документа

1. Скопировать `tz_shortcuter.tex` в новый файл
2. Изменить данные в преамбуле (`\developer`, `\systemname`, etc.)
3. Заполнить разделы содержимым
4. Собрать: `make MAIN=новое_имя`

## Что обновлять вручную

- **«На N листах»** на листе утверждения — параметр `\approvalpage`, 5-й аргумент; сверять с фактическим числом страниц PDF.
- **«Действует с ...»** — 6-й аргумент `\approvalpage`.
- Год в строке «Москва, 2026» на титуле проставляется автоматически (`\the\year`).

## Требования дистрибутива

Проверено на **MiKTeX 25.12** (Windows, user install, `AppData/Local/Programs/MiKTeX`). После установки не хватает пакетов basic-дистрибутива — доустановить:

```bash
miktex packages install extsizes cyrillic tempora titlesec fancyhdr enumitem \
  longtable tabularx caption hyperref booktabs multirow pdflscape setspace \
  footmisc microtype amsmath amsfonts mathtools cite chngcntr etoolbox xcolor listings
```

Замечание: первый запуск `pdflatex` из git-bash может висеть, пока MiKTeX инициализирует базы пакетов — дождаться завершения либо предварительно выполнить `initexmf --update-fndb`.
